# Promotions & Discounts

Open **Shopify → Promotions & Discounts** in TLCDashboard as an administrator. This is a **local planning tool**. Create and edit offer definitions here, check the resolved qualifying variants and compare the offer price with the existing product/variant cost-per-item prepared for Shopify. Create the actual discount manually in Shopify Admin. TLCDashboard does not create, update, schedule, reconcile or delete Shopify discounts, and it cannot verify checkout behaviour.

The displayed contribution is offer price minus the current resolved product cost. For a fixed-total tier, the best and worst cost bounds repeat the lowest- and highest-cost eligible variant because the saved selection permits repeated units. Margin is contribution divided by offer price; markup is contribution divided by product cost. If any ordinary set total is below the configured offer price, profit and margin are withheld rather than assuming Shopify would charge more. This is **not final net profit**: payment fees, postage, labour, electricity, wear and waste are not added unless they are already costed BOM items. Missing product costs suppress the affected profit figure rather than counting them as £0. A red loss warning appears when a qualifying combination's product cost alone can exceed the offer price. The planner shows a local manual-cost override when one is the selected cost source, but cannot verify its itemised BOM breakdown.

The existing multi-collection, product, retained variant, option-value and exclusion selector remains authoritative. Included local collection groups plus explicit selections form a deduplicated pool; exclusions take precedence. Membership and verified product identities are refreshed when the saved plan is reviewed. Existing definitions, quantity tiers, dates and local Drafts remain readable. Planned dates do not schedule Shopify. The Review page includes a copyable setup summary and a link to the verified store's Admin Discounts page when a managed store identity is available. Compare the manually configured discount and cart totals in Shopify before activating it; fixed-total semantics may not match native discounts exactly.

The dedicated Promotions app, its Function, existing credentials and historical receipts are retained but inactive. The seven `TLC_PROMOTIONS_DEV_*` values and read-only PEM mount are no longer startup requirements in the planner image. Remove only those Promotions-specific development container entries after upgrading; keep the product app's `TLC_DEPLOYMENT_*` identity and all ordinary Shopify settings. Historical mutation details remain below for reference, not instructions for the current workflow.

## Retired Shopify publishing design (historical reference only)

## Prepare an offer

1. Create an automatic promotion or a discount code. Use **Exact multi-buy**, **Buy X Get Y**, **Percentage off**, or **Fixed amount off**. Percentage and fixed-amount discounts can apply to selected variants or to a qualifying order. Buy X Get Y can use the same or a separate reward group; customers must put the reward in their cart.
2. Search the existing catalogue. The Collections, Products & Variants, and Combined views filter one shared selector; switching views does not discard selections. Select multiple **local TLC collection groups** to form one deduplicated pool, optionally add whole products, retained variants or option values, then exclude whole products or retained variants. Exclusions take precedence, including when an excluded collection member has no verified Shopify identity. **Specific variant** pins the retained Shopify ID and SKU. Collection and option-value membership is recalculated at each review; changes reach checkout only after fresh approval. Review shows included/excluded selections and the final qualifying variants. Empty or unresolved pools block publication. No catalogue scan or product creation runs in Promotions. Shopify storefront collections are not inferred from local collection groups.
3. Set the minimum quantity, offer amounts and any code restrictions. Native codes can use an existing Shopify customer Segment ID, usage cap and once-per-customer. Exact multi-buy codes support usage caps/once-per-customer in their UK market; this release does not combine a segment with the exact market restriction.
4. Set the UK start and optional end. Local clock-change ambiguities are rejected unless you supply an explicit offset. Set intent to **Live**, then use **Review & Publish**. Future times are scheduled by the reviewed Shopify discount; no second scheduler or product-publisher hook is installed. To pause or archive, save **Disabled** or **Archived** and review the separate deactivation. Historic Shopify records are retained, not deleted.

Review shows the resolved IDs, prices, combination settings, Shopify status and permission findings. Exact offers include a sample cart quote with local list prices and available M2 costs. It estimates item totals before shipping, tax and additional discounts; neither local price nor cost is changed. An **uncertain** result holds the original attempt. Reconcile by reading the retained discount or the permanent ownership marker. A missing or conflicting read does not permit Create to be repeated. Configuration verified is not checkout verified.

## Exact amounts and combinations

- **Dumplings:** select `Keyring = No` across the intended product designs and use `2=9.00`. Use a separate `Keyring = Yes` group with `2=11.00`. At £4.95/£5.95 per item, three standards total £13.95 and four total £18.00; three keyrings total £16.95 and four total £22.00. A mixed pair gets no discount. With both discounts set to allow disjoint product combinations in Shopify, two of each should total £20 before shipping and taxes.
- **Prints:** create separate offers for `Size = A5`, `A4`, or `A3` across selected designs. A pair of different sizes does not qualify for either size's offer.
- **Ornaments:** `3=19.95` allows any three included variants, including identical variants. With repeating sets, four units leave one at its ordinary price; six can use two sets.

The editor shows quantities two through five with optional GBP fixed-total inputs; blank prices disable those rows. Add Quantity Tier supports higher quantities, up to eight valid tiers. Previously saved `quantity=GBP total` definitions remain readable and older clients may still submit that format. The Function uses integer pence. It tests profitable partitions of the highest-priced eligible units and selects the greatest permitted saving; ties favour fewer consumed units, with stable cart-line ordering. Savings are split proportionally with odd pennies assigned by largest remainder. A cheaper set receives no discount rather than a surcharge. Each offer may contain 100 verified variant IDs. The Function bounds checkout to 24 cart lines, 48 eligible units and tier quantities up to 24; oversized carts receive no exact discount, not a silently truncated quote. The private Function configuration is limited below Shopify's 10,000-byte input threshold. The bundled non-customer fixture generator in the Function's `test/cart-fixture.mjs` takes the number of lines and can be piped to Shopify's local Function runner.

Combinations default to off. Overlapping TLC product groups for overlapping schedules are blocked, including Buy X Get Y reward items. Exact offers may opt into combining with **disjoint** product discounts, not with order/shipping discounts in this release. Shopify decides combinations with independently managed discounts and may choose the better incompatible offer. TLC never changes those records. Exact offers are limited to the configured UK market, GBP cart amounts and Great Britain country context; a conflicting delivery country or subscription line is not eligible. Test currency/country switching before any production use.

## Separate Shopify app

[Shopify Functions availability](https://shopify.dev/docs/apps/build/functions) distinguishes Shopify App Store apps on all plans from custom apps with Functions on Plus. For Basic, use a **separate public-distribution TLC Promotions app**. A [limited-visibility listing](https://shopify.dev/docs/apps/launch/distribution/visibility) is possible but still needs [App Store review](https://shopify.dev/docs/apps/launch/app-store-review/review-process). Merchant/dev permissions, an existing theme extension, or a successful Function build do not grant production eligibility. Native percentage, fixed and Buy X Get Y use Shopify's native Admin APIs; they do not require a Function. This release keeps all remote mutation paths development-only, including native discounts.

The existing customisations, upload proxy and product/Orders app are not used for promotions. TLCDashboard authenticates **outbound** directly as the new app with a short-lived [application-only token](https://shopify.dev/docs/apps/build/authentication-authorization/application-only-access-tokens). No public Unraid endpoint is needed. Checkout runs offline from Shopify cart data and an app-owned discount configuration; it never contacts TLC. The future embedded Admin overview must use Shopify-authenticated hosting; this release links to Shopify Admin → Discounts and displays the retained ID/title instead. There is no unauthenticated dashboard bridge or second editor.

Read-only Bundles & Promotions visibility inside the TLC Product app is a separate integration milestone. Its current app manifest has `embedded = false`, a placeholder application URL, and no authenticated embedded Admin backend. Do not expose dashboard routes or change the app installation to simulate this view. A store-bound authenticated app home, session-token validation, deployment and explicit development-app configuration review are prerequisites. Availability in the official Shopify mobile Admin app remains unverified. All editing stays in TLCDashboard.

### Development setup (not production)

1. In Shopify Dev Dashboard, create or grant access to a GBP **development store** and a separate **TLC Promotions Development** app. The repository's existing CLI-linked organization did not list any development stores during M2.2. Keep a separate disposable TLCDashboard catalogue and appdata for this store.
2. From the repository, copy `shopify/promotions/shopify.app.toml.example` to the ignored `shopify/promotions/shopify.app.toml` and link it to the **new development client ID only**. Check `shopify app info --path shopify/promotions` before proceeding. Do not run development/deployment commands against the enclosing `shopify/` app. Run `npm ci --prefix shopify/promotions`, `shopify app function schema --path shopify/promotions/extensions/tlc-exact-multibuy` and `shopify app function build --path shopify/promotions/extensions/tlc-exact-multibuy`. Start the development preview with `shopify app dev --path shopify/promotions --store <development-shop>.myshopify.com`. Confirm the app/store in the CLI before approving installation or releasing anything.
3. Grant the separate app `read_products` and `write_discounts` (Shopify write scope also grants discount read). Exact offers also require `read_markets` for UK context verification. Grant optional `read_customers` only if a native code must target a customer segment and Shopify has approved that access; TLC reads only that segment's ID. Grant no product, inventory, order or customer-data write scope. Add an RSA public JWK to the new app as described in Shopify's application-only token guide. Mount the matching private PEM into the disposable dashboard read-only, mode 0400 or 0600 and readable by its runtime UID. Do not paste or commit the key.
4. Set `TLC_PROMOTIONS_DEV_DOMAIN` (permanent myshopify domain), `TLC_PROMOTIONS_DEV_STORE_ID` (Shop GID), `TLC_PROMOTIONS_DEV_APP_ID` (App GID from that installation), `TLC_PROMOTIONS_DEV_CLIENT_ID`, `TLC_PROMOTIONS_DEV_KEY_ID` and `TLC_PROMOTIONS_DEV_PRIVATE_KEY_PATH`. For exact discounts also set `TLC_PROMOTIONS_DEV_UK_MARKET_ID` to the GBP development store's UK Market GID. The server checks both IDs, the permanent domain, Shopify's development-plan flag and the granted scopes before allowing a write. The production app/shop are explicitly excluded.
5. Use already verified **development-store** product links in that disposable dashboard. Start with native percentage or BXGY, verify Shopify Admin readback, then configure the two disjoint dumpling groups. Use checkout in the dev store with test payments only: try mixed designs, mixed groups, odd quantities, both groups in one cart, a reward added manually, three/six ornaments, and a GBP/GB versus EUR/USD/non-GB cart. Check matched line quantities, final pennies and expiry. Do not mark checkout tested based on GraphQL or local WASM alone.

### Production prerequisites

The public listing, app review, mandatory privacy/compliance webhook handling, appropriate hosted App Home/authentication, any partner identity/business verification and registration fee, and merchant installation must be completed with the account holder. No fee, submission, installation, scope change or release has been initiated. This build's hard development-only mutation gate requires an explicit, reviewed production rollout change even after approval. Do not point it at the production store or reuse current TLC credentials.

For a manual Unraid upgrade, back up the existing appdata and catalogue, use the immutable Docker image and retain the same mounts. The additive promotion table does not migrate stock, BOMs or catalogue identities. With development credentials unset, test local creation, targeting, duplicate, code and scheduling on desktop/mobile; expect the publish action to remain blocked. Keep the separate Shopify app deployment independent from Docker.
